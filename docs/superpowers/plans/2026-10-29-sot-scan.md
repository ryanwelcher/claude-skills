# Source of Truth Scan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `wp-sot-scan` skill that Justin runs weekly in Claude Code to check everything linked in a release's SoT Google Doc, find new candidates, and hand over one dated block to paste at the bottom of a tab.

**Architecture:** Deterministic work lives in zero-dependency Node scripts inside the skill: parsing the Doc export, Trac and GitHub lookups, diffing against last week's state, filtering candidates, rendering the block, and writing it to the repo and clipboard. Judgment lives in `SKILL.md`: the Pass 2 research, deciding which candidates meet the "what makes an item" bar, and fetching Trac query CSVs through Claude in Chrome. Two CLIs split a run around that judgment: `prepare.mjs` (before research) and `finish.mjs` (after).

**Tech Stack:** Node 20+ ESM, built-ins only (`fetch`, `node:test`, `node:assert/strict`), `gh` CLI for GitHub auth, macOS `textutil` + `pbcopy` for the clipboard, Claude in Chrome for Trac queries.

**Spec:** `docs/superpowers/specs/2026-10-29-sot-scan-design.md`

## Global Constraints

- The skill never writes to the Google Doc. The only write to the Doc is Justin's paste.
- No npm dependencies in the skill. Node built-ins only, so there's nothing for Justin to install.
- Block copy, fixed strings: heading `Automated scan results: <Month D, YYYY>`, footer `End of automated scan results: <Month D, YYYY>`, group headings `Changes to linked items` and `New candidates (not in the Doc yet)`, empty-group lines `No changes to linked items` and `No new candidates`.
- No em-dashes anywhere in block output.
- Every finding line ends with a clickable link to its source.
- Trac: never use a headless browser or a spoofed User-Agent. Query CSVs come only through Justin's own Chrome. The timeline RSS feed is the only direct request to Trac.
- Scan files go in the content repo at `<version>/notes/scans/YYYY-MM-DD.md`, with state in `<version>/notes/scan-state.json`. Never write under `releases/`, `layouts/`, `scripts/` or `test/`, which belong to the site skill.
- Content repo (`wptrainingteam/source-of-truth`): commit on `trunk`. No AI co-author or "generated with" lines. Confirm with Ryan before the first push.
- The clipboard step is macOS-only. Confirm Justin is on a Mac before Task 6, Step 5.
- `claude-skills`: push to `trunk`. Commits end with the co-author trailer. A new skill is registered in `wp-sot/.claude-plugin/plugin.json` and the `wp-sot` entry in `.claude-plugin/marketplace.json`, with the wp-sot version bumped to match in both. `git pull` first, because the site session also bumps it.

## Review Focus

1. **The pasted heading comes back from the export with extra formatting**, like `## **Automated scan results: October 29, 2026**` or escaped colons. Expect the block to be found anyway. Test in Task 1.
2. **A person writes notes below a block's footer**, or a block is missing its footer because someone deleted it. Expect text after a footer to count as the Doc's own content, and a block with no footer to end at the next H1 (the next tab). Test in Task 1.
3. **A candidate is struck out in one block and found again next week.** Expect it to stay out, even if it's struck only in an older block. Test in Task 6.
4. **The first run, with no `scan-state.json`.** Expect a baseline to be recorded, no "changed" findings for GitHub, Trac timeline events from the last 7 days still reported, and one line saying it's the first scan. Test in Task 5.
5. **Trac CSV isn't available** because Chrome isn't connected or the fetch failed. Expect timeline-only Trac findings ("Milestone changed on #N, check whether it was punted") and a line saying milestone values weren't checked. Test in Task 5.

### Shared shapes

```js
// Ref: one linked thing. key is the identity used everywhere.
{ key: 'WordPress/gutenberg#81234' | 'trac#66187' | 'url:https://make.wordpress.org/core/...',
  kind: 'github' | 'trac' | 'devnote', repo?: string, number?: number, url: string }

// Snapshot of one ref, as stored in state and returned by lookups.
{ title: string, state: string,           // github: open|closed|merged; trac: new|assigned|closed/fixed…; devnote: ok|missing
  milestone?: string, keywords?: string, error?: string }

// scan-state.json
{ lastRun: 'YYYY-MM-DD', refs: { [key]: Snapshot },
  openCandidates: Finding[] }               // candidates shown and not yet in the Doc or struck

// Finding: one line of the block.
{ group: 'changes' | 'candidates', text: string, url: string, key?: string }

// Work file written by prepare.mjs, read by Claude and finish.mjs.
{ date: 'YYYY-MM-DD', version: string, tab: string, firstRun: boolean, tracCsv: boolean,
  docKeys: string[], struckKeys: string[], findings: Finding[], snapshots: { [key]: Snapshot },
  checked: { linked: number }, openCandidates: Finding[] }   // copied from scan-state.json

// candidates.json written by Claude after Pass 2.
{ checked: string,                         // e.g. "312 Gutenberg PRs, 9 Make Core posts"
  items: [ { group: 'changes' | 'candidates', text: string, url: string } ] }
```
