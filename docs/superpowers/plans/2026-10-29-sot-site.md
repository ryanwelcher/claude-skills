# Source of Truth Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restructure `wptrainingteam/source-of-truth` into one Spacefast site that holds every WordPress Source of Truth (6.2 to 7.2) behind a shared version-switcher header, and add a `wp-sot-site` skill that fills a release's layout from its Google Doc.

**Architecture:** Every source (a Google Doc Markdown export, or a published WordPress post fetched over the REST API and converted to Markdown) goes through one splitter into the same on-disk shape: `releases/<version>/release.json` plus `content/` Markdown files. One root build reads every release, renders each through its layout (the generic one by default) into `dist/<slug>/index.html`, injects the shared header, and renders the newest release at `/`. The importers and build live in the repo, so a cloud run needs only Node and git. The skill is a thin guide over them.

**Tech Stack:** Node 20+ ESM, `node:test` + `node:assert/strict`, `marked` (already used), `turndown` (HTML to Markdown for published posts), Spacefast autodeploy from GitHub.

**Spec:** `docs/superpowers/specs/2026-10-29-sot-site-design.md` (in `~/repositories/claude-skills`). Read it before starting any task.

## Global Constraints

- Content comes only from the source: the Google Doc for 7.2, the published post for 6.2 to 7.1. No invented facts, no rewritten prose, no condensed summaries. Items render with their full text.
- Blocks not in the source are built mechanically (dates, Gutenberg range, counts, standard Make Core links) or left out.
- Nothing from these reaches a page: emoji markers (✏️ 🙏 🔍 🎨 🏈), `<!-- -->` comments, the Doc's Notes and Backlog tabs, the "Important note/guidelines" section, the Tags legend.
- Items flagged 🏈 inside a section are not shown. The Punted block shows only the Doc's Punted tab, and is left out when it's empty or missing.
- Sections render in source order with the source's own headings. The Overview becomes the intro. The Changelog is kept.
- Each release page credits its original author and links its original post (for published-post sources).
- Adding or re-importing one release never changes another release's output.
- The new code reads and writes only `releases/`, `layouts/`, `scripts/`, `test/` and root config. The `7.2/` folder and `.github/workflows/status-7-2.yml` stay byte-for-byte unchanged.
- Release URLs: `/<major>-<minor>/` (for example `/7-2/`, `/6-10/` if it ever exists). `/` renders the newest release.
- `wptrainingteam/source-of-truth` is visible to the whole org: commit locally on `trunk`, and confirm with Ryan before the first push and before every Spacefast step (creating a space, connecting, sharing, retiring the 7.2 space). Never create a branch without asking.
- Commit messages in the content repo have no AI co-author or "generated with" lines. Commits in `claude-skills` end with the co-author trailer and bump the devrel version in both manifests.

## Review Focus

1. **The Doc export comes back as a Google sign-in page or is missing tabs.** Expect the importer to stop with a clear message, not write an empty release. Test in Task 3.
2. **Version ordering past x.9** (`6.10`, `7.10`). Expect numeric order, so the newest release is really newest. Test in Task 5.
3. **Re-importing a release whose items were renamed or removed.** Expect no stale item files left behind, and `release.json` fields and `layout/` kept. Test in Task 2.
4. **Published posts with images, video embeds and `<kbd>`/`<code>`.** Expect images and iframes to survive with absolute URLs. Test in Task 4.
5. **A marker or comment slipping past the importer** (for example a 🔍 inside a heading, or a multi-line comment). Expect the build to fail. Test in Task 5.

### Shared data shapes (used by every task)

```js
// Structure: what split() returns and what readRelease() returns.
{
  intro: string,                 // Markdown (the Overview, plus the welcome text before it)
  changelog: string,             // Markdown, '' when absent
  punted: string,                // Markdown, '' when absent
  sections: [ {
    title: string, slug: string, tags: string[], body: string,   // body = text before the first item
    items: [ { title: string, slug: string, tags: string[], flags: string[], body: string } ]
  } ]
}

// release.json
{
  "version": "7.2", "title": "WordPress 7.2 Source of Truth",
  "releaseDate": "December 8, 2026", "gutenbergRange": "23.7 – 24.3",
  "author": { "name": "", "url": "" },
  "published": "",                       // ISO date of the source post, '' for an unpublished Doc
  "updated": "",                         // ISO date of the last import
  "source": { "type": "gdoc" | "gutenbergtimes" | "nomadblog", "id": "", "url": "" },
  "layout": "generic",                   // or "own" → releases/<v>/layout/layout.html
  "milestones": { "beta1": "", "rc1": "", "final": "" }   // optional; timeline only when present
}
```

Item `flags` use the existing names: `edit`, `blessed`, `check`, `visuals`, `punted`. Tags are lowercase audience names (`end user`, `theme builder`, …). An item with no tags filters by its section's tags.

**Layout slot contract.** These are HTML comments in `layout.html`, each replaced by `renderPage`:

| Slot | Filled with |
|---|---|
| `<!-- sot:head -->` | `<title>`, description, `<link rel="canonical" href="/<slug>/">` |
| `<!-- sot:header -->` | `renderHeader(...)` |
| `<!-- sot:hero -->` | Eyebrow `WORDPRESS X.Y · RELEASED <releaseDate>` (or `· SHIPS <releaseDate>` when `published` is empty). H1 is `meta.title`. The intro is the first paragraph of `structure.intro`, and the rest of the intro goes under it. Byline: author name and link, "Updated <updated>", reading time (`Math.ceil(words / 200)` minutes and the word count). For published-post sources, add "Originally published on <site> ↗" linking `source.url`. |
| `<!-- sot:stats -->` | Up to four stats from: release date, number of sections, number of items, Gutenberg range. A stat whose value is missing is skipped. |
| `<!-- sot:timeline -->` | Milestones from `meta.milestones`. The slot is empty when there are none. |
| `<!-- sot:filter -->` | One pill per tag used on the page, in first-seen order. |
| `<!-- sot:toc -->` | Numbered list of sections, with items nested. |
| `<!-- sot:sections -->` | Each section as `<section class="section" id data-tags data-title>` with its H2, its `body` and its items. Each item is `<article id data-tags data-title>` with an H3, tag chips and its Markdown body rendered with `marked`. Items flagged `punted` are skipped. Untagged items use the section's tags. |
| `<!-- sot:punted -->` | The punted block from the 7.2 example with `structure.punted` rendered. The slot is empty when `punted` is `''`. |
| `<!-- sot:changelog -->` | `structure.changelog` rendered under "Changelog". |
| `<!-- sot:resources -->` | Make Core cycle page `https://make.wordpress.org/core/X-Y/`, the dev notes tag `https://make.wordpress.org/core/tag/dev-notes+X-Y/`, and for published-post sources the original post. |
