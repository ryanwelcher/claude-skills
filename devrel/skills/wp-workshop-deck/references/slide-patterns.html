Section 2 · Anatomy · ★ remember this slide

The opt-in pair

block.json

"supports": { "interactivity": true }

Loads the engine. It enqueues the @wordpress/interactivity runtime and makes view.js an ES module.

⇄

render.php

data-wp-interactive="iapi-gallery"

Gives the engine a place to bind. It marks where the Interactivity API takes over, and it ties every directive underneath it to the iapi-gallery namespace.

If you miss the flag, the runtime never loads. If you miss the directive, it has nothing to bind to. You need both.

Section 4 · IAPI Primer · 0:31–0:39

What is the Interactivity API?

It's the standard way to add front-end interactivity to blocks, and it ships with Core.

  • Instead of every plugin bringing its own JS (and loading duplicates of it), everyone uses one pattern
  • It works for a toggle button, and it works for live search, carts, and instant navigation
  • Blocks can share state, so "add to cart" in one block updates a separate cart block automatically

Already running in Core

  • Search
  • Query Loop
  • Navigation
  • File
  • Image lightbox
Section 4 · IAPI Primer

Under the hood

Preact + Signals

Hydration (taking over the server's HTML in the browser), client logic, and client-side navigation. It's tiny, and you never touch it directly.

HTML directives

data-wp-* attributes that both the client and the server understand.

HTML Tag Processor

Server-side logic in plain PHP. There's no Node.js SSR anywhere in the stack.

The trick is that both the client and the server can read the directives, and that's what makes Section 7's no-flash first paint possible.

Section 4 · IAPI Primer

Declarative, not imperative

// imperative: the HOW (plain JS, for comparison)
let current = 1;
nextButton.addEventListener( 'click', () => {
    current++;
    counter.textContent = current;
} );

You change the value, then you update the DOM yourself.

<!-- declarative: the WHAT (trimmed) -->
<button data-wp-on--click="actions.nextImage">
<p data-wp-text="context.currentSlide"></p>

// view.js
nextImage: () => {
    const ctx = getContext();
    ctx.currentSlide++;
},

You change the value. The directives keep the DOM in sync.

Directives work the same way: you describe what the UI should be for a given state, never how to update the DOM step by step.

That right-hand side is what you'll build in Section 5.

Section 4 · IAPI Primer · ★ the loop

The round-trip loop

directivereads the store
eventfires an action
actionmutates context
re-renderdirectives update
⟲ …and the directives read again

Every section from here is this loop with more parts.

You do the mutation and the runtime handles every re-render. That's the deal.

Section 4 · IAPI Primer · ★ the distinction

Three kinds of data

Global state · when blocks share data, or the server seeds a value

wp_interactivity_state(
    'iapi-gallery',
    array(
        'noPrevSlide' => true,
        'imageIndex'  => …,
    )
);
iapi-gallery-slider.php · Section 7

Local context · when each instance is independent

$context = array(
    'currentSlide' => 1,
    'totalSlides'  => 3,
);
…
<?php echo wp_interactivity_data_wp_context( $context ); ?>
<!-- outputs:
  data-wp-context='{"currentSlide":1,"totalSlides":3}' -->
render.php

Derived state · when a value can be calculated

state: {
    get imageIndex() {
        const ctx = getContext();
        return `${ ctx.currentSlide }/${ ctx.totalSlides }`;
    },
},
view.js

Context belongs to each instance. State is shared, and it can be derived.

Section 7 · Server-Side Injection · 0:59–1:12

The render filter walk

The count is still hardcoded to 3. On the server, the filter sees the real inner blocks, so it can count them.

Land on the wrapper with next_tag()
set_bookmark( 'main' )
Scan forward, counting slide classes
seek( 'main' ) to jump back
set_attribute( 'data-wp-context', … ) with the real count
add_filter(
  'render_block_iapi/gallery-slider',
  'iapi_gallery_slider_inject_context',
  10, 2
);

The filter counts the slides inside the slider. Because the hook name includes our block name, it never runs for any other block.

We do not set data-wp-interactive on inner blocks. Descendants inherit the wrapper's namespace. ★
